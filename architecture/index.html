Zone Trip
Simulator Manifesto White paper

System architecture

A governed path from utterance to public reflection.

Zone Trip separates the real booth from the browser simulation. The real installation is a microphone connected to one Linux box. The public Pages front end simulates the booth. Aru treats every derived signal as a typed epistemic object, requires a transformation warrant, pauses for steward review, and burns reconstructive daily material only after that semantic review is complete.

Runtime boundaries

Three deployments, one contract.

The same constitutional processor contract is used across the local booth, Pages simulator, and Cloud Run simulator. Only the local booth is the charter-compliant participant-material runtime.

Real booth

Local Linux box

Microphone capture, Whisper STT, Ollama Gemma, processor service, and durable model.md state run on one machine inside the booth boundary.

Review surface

GitHub Pages

The browser renders the Three.js booth, VAD-based silence cue, world-model drawer, and optional development text input. It is a simulator, not the physical participant interface.

Sizing simulator

Cloud Run GPU

Cloud Run uses an L4 GPU, min-instances=0, and the same in-container Ollama/Gemma path for fidelity testing against equivalent local hardware.

Processing loop

Models propose transformations; the pipeline governs them.

  1. Capture

    Audio enters from the booth microphone or simulator browser.

  2. Transcribe

    Whisper receives temporary audio and returns request-local STT.

  3. Redact and constrain

    The processor reads immutable charter.md, removes reconstructive detail, and rejects prohibited use.

  4. Create typed objects

    Derived candidates carry object type, source dependency, uncertainty, prohibited claims, and retention class.

  5. Issue warrants

    Every derived object receives a transformation warrant and deterministic constitutional checks.

  6. Review, publish, and burn

    A steward reviews the daily draft. Approval publishes it, signs an attestation, burns temporary artifacts, and verifies deletion.

Daily batch mirror

Reason once over derived notes, not a raw day transcript.

The configured local model is gemma3:12b, which has a nominal long context window. The booth still should not save or reason over a full raw day transcript. In daily batch mode, each utterance becomes charter-filtered segment notes; the end-of-day pass integrates those notes into model.md and clears the intermediate file.

During the day

Segment notes

Speech becomes temporary STT, then derived notes for tensions, contradictions, absences, patterns, minority signals, questions, and rejected boundary pressure.

End of day

Integrated model

The processor reads charter.md, current model.md, and day notes, then writes one replacement model rather than a chain of per-turn summaries.

After finalization

Reviewed burn

Segment notes and the epistemic ledger remain available through semantic review. They are cleared only after /review-day; the public reflection, attestation, and burn receipt survive.

Durable state

Only the public artifact and process attestations survive.

The model file is not source material. It should contain abstracted tensions, contradictions, absences, symbolic patterns, minority signals, open questions, and rejected boundary material.

Allowed

  • Derived signals
  • Uncertainty and contradiction
  • Absences and minority signals
  • Rejected boundary categories
  • Review attestation and draft hash
  • Verified burn receipt

Forbidden

  • Raw transcript or quotes
  • Names, factions, subgroup maps, or identity exposure
  • Rankings, counts, scores, or representational claims
  • Recommendations, mandates, diagnoses, or governance action

Silence and scale-to-zero

No speech is no work.

The browser simulator uses lightweight Web Audio RMS VAD. One minute without detected speech stops capture and dims the eight overhead lights. Cloud Run is deployed with min-instances=0; the visual dimming is a cue that the processor simulator can be idle or scaled to zero.

Development path

Text input is for developers only.

Local installs match the Pages simulator by default: same scene, same microphone-first threshold, and no text drawer. Developers can opt into a drawer text form that posts to /process-stt when they need to test the STT-output side of the loop without recording audio. The physical booth remains microphone-only.

Steward checkpoint

Semantic audit happens while comparison remains possible.

After the burn, Aru can prove which process and policy versions ran, but it cannot honestly promise retrospective semantic reconstruction. The steward workspace therefore presents the draft and its temporary support graph before deletion.
